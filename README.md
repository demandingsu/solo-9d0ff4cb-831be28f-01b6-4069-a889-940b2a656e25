# 冷库 A/B 除霜策略耗电对比分析

Flask + SQLite 的小型分析网页：导入「轮次计划」「实际切换记录」「每分钟用电量」三份 CSV，
按轮次给出有效配对数和 **B − A 平均耗电差**，并逐分钟列出哪些配对因何剔除；
在网页上更正切换时刻后，只重算受影响轮次。

## 快速开始（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据落在命名卷 `coldstore-data` 的 `/data/coldstore.sqlite3`；容器重启数据仍在。

本地开发运行（需要 Python 3.11+ 与 Flask）：

```bash
python -m pip install -r requirements.txt
COLDSTORE_DB=./data/coldstore.sqlite3 python -m coldstore.web
# 或 flask --app coldstore.web run
```

## CSV 格式

所有时间均为 **UTC 整分钟**，接受 `YYYY-MM-DD HH:MM`、`YYYY-MM-DDTHH:MM`、末尾 `Z` 或 `+00:00`；
拒绝非整分钟、非 UTC 偏移。表头大小写与首尾空格不敏感。

**轮次计划** `rounds.csv`

| 列 | 含义 |
| --- | --- |
| `round_id` | 轮次编号，唯一 |
| `a_start`, `a_end` | A 窗 `[a_start, a_end)` |
| `b_start`, `b_end` | B 窗 `[b_start, b_end)` |

校验：两窗等长、互不重叠（首尾相接允许）、终点晚于起点。

**实际切换记录** `switches.csv`

| 列 | 含义 |
| --- | --- |
| `switched_at` | 从这一分钟起实际策略变为 `strategy` |
| `strategy` | `A` 或 `B` |
| `round_id` | 可选；留空 = 对全部轮次生效，填写 = 仅作用于该轮 |

**每分钟用电量** `readings.csv`

| 列 | 含义 |
| --- | --- |
| `minute` | UTC 整分钟 |
| `kwh` | 该分钟耗电量（kWh，非负） |

`examples/` 下有三份可直接导入的示例，覆盖：

| 轮次 | 预期 | 场景 |
| --- | --- | --- |
| R1 | 60 有效对 | 正常 |
| R2 | 45 有效对 | A 窗起点才切回 A（前 10 分钟不足）；B 窗第 5 分钟才切 B |
| R3 | 44 有效对 | B 窗第 5 分钟才切 B；另有 2 个分钟缺读数 |
| R4 | 30 有效对 | 两次切换都恰好提前 10 分钟，边界有效 |
| R5 | 不可比较 | B 窗内实际仍是 A → 全部 20 对剔除 |

## 计算口径

1. **配对**：A 窗第 *i* 分钟与 B 窗第 *i* 分钟配对（相同分钟偏移）。
2. **有效对**：同一偏移上
   * A、B 两侧都有用电读数；且
   * 该分钟的实际策略分别等于计划策略 A / B；且
   * 该分钟距该策略区间起点 ≥ 10 分钟（即已按该策略连续运行满 10 分钟）。

   任一侧不满足，整对剔除，并记录具体原因（缺读数 / 策略不符 / 无法确认策略 / 未满 10 分钟）。
3. **汇总**：有效对数的 `(B − A)` 算术平均，单位 kWh/分钟；正值表示 B 更耗电。
   没有有效对 → 该轮 `不可比较`，平均值为空。
4. **连续运行**从切换记录给出的策略区间起点算起；同策略的重复记录会合并，不打断连续性。
   时间窗左闭右开，终点那一分钟不属于窗口。

### 更正与增量重算

- 更正切换时刻（以及可选策略、作用轮次）后，比较**更正前后每个计划窗内逐分钟的
  `(实际策略是否正确, 是否已运行满 10 分钟)` 状态**；状态有任何变化才重算该轮。
- 因此切换记录落在窗外也可能触发重算（例如把 B 窗前的切换从 12:50 改到 12:51，
  B 窗 13:00 起就不再满 10 分钟）；窗内切换若没有改变任何分钟状态则不会重算。
- 切换记录更新、该轮配对明细、汇总在同一事务内提交；任何异常整体回滚，
  原记录与旧结果保持可查。每次导入/更正都写入 `audit_log`。

## 数据库结构

`rounds`（轮次计划）、`switches`（切换记录，可更正）、`readings`（分钟读数）、
`results`（每轮汇总缓存）、`result_pairs`（逐对明细与剔除原因）、`audit_log`（操作日志）。

## 已知限制 / 待办

- 10 分钟连续运行按**每个配对分钟**判断（因此窗内切换会只剔除窗首若干对）。
  若业务要求「整窗都必须提前 10 分钟已运行」，只需改为按窗首判定。
- 切换记录只表达「从某分钟起策略变为 X」，不表达切换耗时/过渡分钟；如需过渡期
  不可用，可作为额外剔除原因加入。
- 导入为**全量替换**（三份文件一起换），不支持追加或单轮增量导入。
- 未做鉴权与多用户隔离；生产部署需替换 `COLDSTORE_SECRET` 并置于反向代理之后。
- 本环境无 Docker，`Dockerfile` / `docker-compose.yml` 按标准写法提供但**未实际构建运行**；
  已用本地 Python 进程 + 示例 CSV 完成端到端 HTTP 自测（导入、展示、跨窗更正）。
- 更正失败（输入非法、记录冲突）与重算异常都会回滚；但若进程在提交后崩溃，
  以 SQLite 事务保证的前一状态为准，没有额外的 WAL 备份/恢复界面。
- 页面一次渲染全部轮次与全部配对明细（示例规模很快）；轮次或分钟数很大时
  需要分页或按需加载 `/api/rounds/<id>/pairs`。
